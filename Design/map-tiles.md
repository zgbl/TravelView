# 地图底图选型

## 当前状态

桌面端 MVP 用的是 **OpenStreetMap 官方瓦片服务器**
（`tile.openstreetmap.org`）。这是开发期的临时选择，**不能带到线上**。

## 两个必须解决的问题

### 1. OSM 官方瓦片不允许产品化使用

OSM 基金会的瓦片使用政策明确写着：那台服务器由捐款维持，只供**轻量使用和开发测试**。
一个真实用户在跑的 App 属于滥用，流量上来会被直接封 IP。这不是灰色地带，是明确禁止的。

### 2. 用第三方瓦片 = 把用户的行踪送给别人

这一条更要命，而且和我们的核心卖点直接冲突。

瓦片是按需请求的：用户打开某次旅行的地图，浏览器就会向瓦片服务器请求那一带的方块。
**对方的日志里因此有了一串坐标 + IP + 时间**——足以还原这个人去过哪里。

我们一边宣传"你的照片从不上传"，一边把用户的行踪泄露给第三方地图商，
这个矛盾迟早会被人指出来，而且会很难看。

## 方案对比

| 方案 | 成本 | 隐私 | 说明 |
|---|---|---|---|
| **Protomaps (自托管 pmtiles)** | 存储费 + R2 零出网费 | **完全不外泄** | 全球底图打包成**一个文件**放对象存储，按需 range 请求。推荐 |
| MapTiler / Stadia | 免费额度后按量 | 对方能看到 | 起步最快，但隐私说不清 |
| Mapbox | 免费额度后按量 | 对方能看到 | 样式最好看 |
| 自建瓦片服务器 | 服务器 + 带宽 | 不外泄 | 运维负担重，没必要 |

## 推荐：Protomaps

一个 `.pmtiles` 文件就是整个星球的矢量底图（全球约 100 GB，
只要北美 + 中国的话小得多）。放进 Cloudflare R2，客户端用 HTTP Range
请求需要的那一小段。

它同时满足这个项目的三条原则：

- **零服务器逻辑**：R2 就是个静态文件桶，我们不跑瓦片服务
- **零出网费**：R2 不收出网流量费，这对图片型产品是决定性的
- **零行踪泄露**：请求打在我们自己的域名上，没有第三方

代价是要自己做一次样式（Protomaps 有现成的基础样式可以改），
以及底图数据要定期更新（一年一两次足够，旅行地图不需要最新的道路）。

## 落地顺序

1. **现在（开发期）**：继续用 OSM 官方瓦片，**但必须显示署名**——
   ODbL 许可要求署名，这是法律义务不是礼貌。已经加上了。
2. **分享页上线前**：切到 Protomaps + R2。网页端用 MapLibre GL JS
   （原生支持 pmtiles 协议），桌面端 flutter_map 换成 vector 瓦片源。
3. **中国大陆的用户**：另需考虑坐标系（WGS-84 vs GCJ-02）和测绘资质问题，
   届时可能要换成国内合规的地图服务。这块留到有国内用户再说。

## 一个可以变成卖点的细节

自托管底图意味着**分享出去的游记网页，地图也是我们自己的**。
将来可以做成品牌化的样式（比如复古地图风、极简黑白风），
让 TravelView 的游记页一眼就能认出来。用第三方瓦片就永远做不到这一点。
