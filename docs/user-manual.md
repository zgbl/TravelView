# TravelView 使用手册

> 本手册随功能同步更新。**改动任何快捷键或鼠标行为，必须同时改这份文档。**
> 最后更新：2026-09-05

---

## 1. 核心概念（三句话）

- **照片库就是一个普通文件夹**。照片按拍摄日期存成普通文件，
  不装任何软件也能在访达里打开。`catalog/` 里的东西全是派生数据，
  删掉后用「重建索引」就能完整恢复。
- **选取不等于删除**。选取只是给照片打一个标签，决定它进不进某个专辑。
  没被选取的照片一直在库里，文件一个字节都没动。
- **手机上的照片只读**。App 只会从手机复制，从不修改、从不删除。

---

## 2. 照片查看器

点任意缩略图打开。这是挑图时待得最久的地方，所有操作都能用键盘完成。

### 2.1 挑图（最常用）

| 按键 | 动作 |
|---|---|
| **空格**（或 Enter / P） | 选取 / 取消选取这张 |
| **X**（或 Backspace） | 移出选取 |

**选取和翻页是分开的两件事**：按空格只改选取状态，画面**停在原地**，
中央会闪一个明确的提示告诉你选上了还是取消了，想反悔再按一次即可。
翻页请用方向键或滑动。

选中的照片有一圈青色边框，底部常驻显示当前专辑已选多少张。

### 2.2 翻页

| 操作 | 平台 | 说明 |
|---|---|---|
| **左右滑动** | macOS | Magic Mouse 在鼠标背上左右扫，或触控板双指左右滑 |
| **滚轮上下** | Windows | 滚轮就只有上下，所以用上下 |
| 方向键 ← → ↑ ↓ | 全平台 | 上下左右都能翻 |
| Home / End | 全平台 | 跳到第一张 / 最后一张 |
| 左右两侧的箭头按钮 | 全平台 | 鼠标操作 |

**为什么 macOS 只认左右**：上下滑是"看这一张"的动作，
横向才是"换一张"，这样两种手势不会互相干扰。
**放大状态下滚动不翻页**，改为平移图片——否则看局部时会乱跳。

### 2.3 缩放

| 操作 | 说明 |
|---|---|
| **双击** | 在 1x 与 2.5x 之间切换 |
| **Z** | 同上，键盘版 |
| **Cmd/Ctrl + 滚轮** | 无级缩放 |
| 放大后**拖动** | 平移 |

滚轮**不**直接缩放，因为它已经用于翻页了——两者抢同一个手势会很混乱。

### 2.4 旋转

| 按键 | 动作 |
|---|---|
| **]** | 向右转 90 度 |
| **[** | 向左转 90 度 |

顶部也有两个旋转按钮。三件事值得知道：

- **永久生效**：直接写回原文件，在访达、预览、任何软件里打开都是转好的方向
- **画质零损失**：只改 EXIF 的方向标记，不重新编码像素，速度也极快
- **拍摄时间不变**：EXIF 时间原样保留，文件修改时间也会恢复成原值

视频（MOV）不支持旋转。

### 2.5 其它

| 按键 / 操作 | 动作 |
|---|---|
| **I** | 显示/隐藏信息面板（时间、GPS、尺寸、设备、库内路径，可选中复制） |
| **Esc** | 关闭查看器 |
| 顶部「在访达中显示」 | 在访达里定位到这个原文件 |
| 顶部「用默认程序打开」 | 用系统默认程序打开原图 |

视频显示的是首帧，点「用系统播放器打开」交给系统播放。

## 3. 主界面

### 3.0 时间范围（照片视图和地图共用）

顶部有一条时间范围筛选。**照片库永远只有一个、装全部照片**；
想做哪一段行程的报告，就把范围调到那一段 —— 照片视图和行程地图会同时跟着变。

**绝不需要为了做某次旅行的报告，把照片再导一份到新文件夹。**

| 控件 | 说明 |
|---|---|
| 「全部」 | 取消筛选，看整个库 |
| 年份快捷键 | 一键切到某一年 |
| 自定义时间范围 | 打开对话框，**日期和时:分都能直接改** |
| 右侧计数 | 显示"范围内 N / 总数 M 张" |

对话框里开始和结束各有一个日期按钮和一个时间按钮，点哪个改哪个。
**精确到分钟**，所以同一天里想把上午、下午切成两段行程也做得到。

范围一变，行程地图会立刻重算路线、里程和天数。

### 3.1 侧栏

| 项 | 说明 |
|---|---|
| 打开照片库 | 选一个文件夹作为照片库。空文件夹会自动初始化 |
| 从手机导入 | USB 连接 iPhone 后直接读取（见下节） |
| 从文件夹导入 | 从任意文件夹导入，也可用于导入相机 SD 卡 |
| 照片 / 行程地图 / 生成旅行回顾 | 三个视图之间切换 |
| 重建索引 | 删掉 `catalog/` 也能从文件和 sidecar 完整重建 |
| 校验完整性 | 逐个重算内容哈希，检查有没有文件损坏或丢失 |

### 3.2 顶部统计

照片总数、占用空间、含 GPS 的比例、当前专辑已选数、待处理项。

### 3.2 工作进度（保存/打开）

时间范围下面那一行就是工作进度条。

| 操作 | 说明 |
|---|---|
| 保存工作进度 | 起个名字存下来，例如「横穿美国 2025」 |
| 打开 | 列出已保存的进度，点一下就切过去 |
| 另存为 | 基于当前状态另存一份，用来做同一趟旅行的不同分段 |

一份进度记录的是**怎么看这个库**：时间范围、挑选用的专辑名、当前视图、聚类粒度。
它存在照片库自己的 `catalog/projects.json` 里 —— **把库拷到移动硬盘、换台电脑打开，
进度跟着一起走**，不是绑在这台机器上。

进度里**不含任何照片数据**，删掉一份进度不会丢任何照片或选取记录。

### 3.3 关掉再打开会怎样

**上次的工作状态会自动恢复**：上次打开的照片库、时间范围、当前视图（照片/地图）、
专辑名、聚类粒度，下次启动直接接着用，不用重新选文件夹。

要在多个行程报告之间来回切换，用上面的**工作进度**功能。

这些状态存在系统的应用支持目录里
（macOS: `~/Library/Application Support/TravelView/settings.json`），
**只记录"上次做到哪里"，不含任何照片数据** —— 照片和标签的真相始终在照片库的
`.tvmeta.json` 里。所以选取、旋转这些操作本来就是立即落盘的，从来不会因为关闭 App 而丢失。

### 3.4 状态栏

左边是当前操作的进度，右边是**缩略图后台预生成**的进度。
预生成不影响任何前台操作，可以边生成边浏览、边导入。
生成好的缩略图缓存在 `catalog/thumbs/`，下次打开秒开。

## 4. 从 iPhone 导入

1. 数据线连接 iPhone，手机上点「信任此电脑」，**保持手机解锁**
2. 侧栏点「从手机导入」，选择设备
3. 用「按日期筛选」限定范围，或逐张勾选
4. 可以填一个旅行名字，这批照片会被自动打上该标签
5. 点「导入到照片库」

**注意事项**

- 锁屏状态下连不上，PTP 会话打不开
- 被 iCloud「优化存储」抽走原图的照片，这条路读不到
  （手机上只剩缩略图，只有装在手机上的 App 才能把原图拉回来）
- 相册结构、收藏这些信息拿不到，它们只存在 Photos 数据库里
- 有些文件没有拍摄时间，设了日期范围时会被排除，界面上会提示有多少个

## 5. 行程地图

时间范围由顶部的筛选条控制（见 3.0），改了就即时重算。

| 控件 | 说明 |
|---|---|
| 长途自驾 / 城市游玩 | 聚类粒度。长途半径 1500 米，城市 300 米 |
| 驾车 / 步行 / 直线 | 路线形态。前两个会贴合实际道路 |
| 「贴合道路」按钮 | 算一次真实道路路线，结果永久存在照片库里 |
| 齿轮图标 | 选择路径规划服务（见下） |
| 点击节点或右侧列表 | 地图飞到该地点 |
| 右侧时间线 | 每个地点显示"到达 - 离开"，每天显示当天的时间跨度 |
| 右侧小封面 | 点开查看该地点的照片 |

圆点大小代表照片数量。**实线是自驾或步行，紫色虚线是飞行段**
（由两点间的平均速度推断）。右上角显示天数、地点数、总里程、照片数。

**道路路线**

选「驾车」或「步行」后点「贴合道路」，路线会贴合真实公路，
里程也从直线里程换成道路里程（更接近实际）。

- **算一次，永久存**。结果写进照片库的 `catalog/routes.json`，
  换模板、改时间范围、换台电脑都不会再请求网络
- **飞行段永远画直线**（紫色虚线）。速度超过 300 km/h 的段自动识别为飞行
- **某段取不到道路时会退回直线，并用浅灰色标出**，一眼能看出是哪几段
- 服务不可用也不会白屏 —— 行程图任何情况下都画得出来

**关于服务选择**（齿轮图标）：

| 选项 | 说明 |
|---|---|
| openrouteservice | 托管服务，注册即有免费额度，现在用这个最快 |
| OSRM | 自托管，没有额度限制，但预处理路网很吃内存 |
| 只用直线 | 不联网 |

两个联网选项都基于 OpenStreetMap，**结果允许永久保存** ——
这是能把路线写进分享页并十年后仍可显示的前提。

没有 Google 是有原因的：它的条款既限制存储路线内容，
又要求路线必须显示在 Google 地图上、不能与其它底图混用，
而我们用的是自托管底图，两条都冲突。

**路线是推算的**，不是你的真实轨迹 —— 我们只知道每一站的位置，
不知道你当时是不是绕了风景道。如果你有行车记录仪或运动手表的 GPX 轨迹，
以后可以导入，把路线升级成真实走过的路。

## 5.5 生成旅行回顾

按「站」自动精选照片，你确认或修改。

每一站有**两条并列的照片轨道**：

- 上面一条是**精选进回顾**的（大图，封面有标记）
- 下面一条是**这一站的全部照片**（小图，已选中的会高亮）

**两个动作是分开的**（挑图时既要看得清，又要选得快）：

| 操作 | 结果 |
|---|---|
| **点照片本身** | 打开大图。翻页范围是**这一站的全部照片**，可以一张张看过去 |
| **点右上角的圆圈** | 直接选取 / 取消，不打开大图 |
| 大图里按**空格** | 选取 / 取消，画面停在原地 |

三者改的是同一个状态 —— 选取就是给照片打「精选」标签，**立即写进照片库**，
关掉 App 也不会丢。

| 按钮 | 说明 |
|---|---|
| 每站 N 张 | 自动精选的目标张数（自动 / 3 / 5 / 8 / 12） |
| 重算建议 | 只重新计算建议，不改动你已有的选取 |
| 某一站的「自动精选 N 张」 | 把这一站的建议应用成实际选取（会覆盖该站已有选取） |
| 自动精选全部站 | 对所有站应用建议，会先问一次 |
| 清空 | 清掉这一站的选取（照片不受影响） |

**关于「去重信号 N / M」**：自动去重依赖清晰度、感知哈希、人脸数这些信号，
它们在后台随缩略图一起计算。**没算完之前，去重只能靠拍摄时间兜底，
重复照片会偏多**。等这个数字追平总数，精选质量会明显提升。

## 5.5.1 每一站的文字

每个站卡片底部有**小标题**和**说明文字**两个输入框，写完自动保存到照片库
（`catalog/notes.json`），跟着库走。

### 自动生成（不用 AI，默认就能用）

每个站有一个**自动生成**按钮，工具栏还有**自动生成全部文字**。
它不联任何 AI，只把已经知道的东西写成一句人话：

> 9 月 14 日下午到亚利桑那州页岩城，停留约 2 小时，拍了 12 张照片。
> 从拉斯维加斯开过来约 431 公里。这一带有马蹄湾、羚羊峡谷、鲍威尔湖。

**一个字都不推测** —— 没记录的天气、吃的、同行的人，它一律不写。
所以可以放心批量生成，再自己改。

批量生成**只补空白的站**，你已经写过的一律不碰。
地标的措辞永远是"这一带有"，不是"参观了" —— 我们并不知道你去没去。

### 让 AI 起草

两种方式，都不强制联网：

| 方式 | 说明 |
|---|---|
| **复制提示词** | 把整理好的提示词复制走，粘到任何 AI 里（ChatGPT 网页版也行），再把结果贴回来 |
| **用我的 AI 起草** | 填好自己的 AI 服务后，一键生成，结果直接落进输入框可以改 |

**费用由你自己承担**，我们不经手也不加价。设置里可以填任何兼容 OpenAI 接口的
服务：OpenAI、DeepSeek、Kimi，或者本机跑的 Ollama。

**发送给 AI 的只有文字**：地名、时间、停留时长、照片张数、附近地标。
**照片一张都不会发出去。**

### 地名和附近地标

点「查地名和附近地标」会从 OpenStreetMap 查一次，结果永久缓存在照片库里，
不会重复请求。附近地标只是"这一带有什么"，提示词里会明确告诉 AI
**不代表你去过**，避免它编出"我参观了 XX"。

### 关于来源标记

文字右上角的标记说明它是谁写的：手写 / 按时间地点自动生成 / AI 起草。
**你改动任何一个字，标记就加上"已修改"**。
这不是洁癖 —— 重新生成时不能覆盖掉你手写的内容，得先知道哪些是你写的。

## 5.6 导出 Story 网页

在「生成旅行回顾」里挑好照片后，点顶部的**「导出 Story 网页」**，
会生成一个**完整、自包含、可离线打开**的网页包，并自动在浏览器里打开。

产物在照片库里：

```
<照片库>/views/by-trip/<slug>/
  index.html      渲染器，双击就能看，不需要联网也不需要构建
  story.json      manifest（几十 KB）
  photos/*.webp   网页用派生图，长边 1600，已剥掉全部 EXIF
  thumbs/*.webp   缩略图
```

**原图一张都不会被复制进去。** 这个目录就是将来要上传的全部内容 ——
40 张照片大约 10MB，而不是几百 MB 的原图。

网页里有什么：

- 封面大图 + 标题 + 天数/站数/里程/照片数
- 右侧固定的地图，**滚到哪一站，地图就跟到哪一站**
- **小车沿着实际道路行驶**，走过的路线逐渐画出来，车头跟着道路方向转
- 每一站：封面大图 + 照片网格，点开可看大图
- 结尾的数据总结卡片（**专门为截图分享设计**）

**目前的限制**：地图用的是 OSM 的公共瓦片，只适合本地预览；
正式发布前要换成自托管的底图（见 `Design/map-tiles.md`）。

### 导出的网页里有什么

| 区块 | 说明 |
|---|---|
| 封面 | 大图 + 天数 / 站数 / 里程 / 张数 |
| **行程全览** | 整趟旅行的完整路线和编号站点，**点站点跳到对应的照片** |
| 每一站 | 标题、时间、你写的文字、精选照片 |
| 侧边地图 | 跟着阅读走：滚到哪一站，小车开到哪一站 |
| 结束卡片 | 汇总数字 |

**照片和地图是互相指认的**：鼠标移到某张照片上，地图会指出它是在哪拍的
（照片自带 GPS）；点地图上的站，正文就跳到那一段。点照片进入全屏后，
左右方向键在**这一站**的照片之间翻，地图上的位置跟着一起动。

## 5.7 发布到网站

导出之后，工具栏的**发布**按钮把这份产物传到网站，换回一个**永久公开链接**。

### 第一次要先登录

主界面右上角有**登录**按钮（不用等到发布时才处理账号）。点它，
App 会显示一串短码（形如 `KDR8-Q2M7`）：

1. 点「打开网页」，浏览器会打开网站的 `/link`；
2. 登录后把那串码敲进去，点确认；
3. 回到 App —— 那个窗口会自己关掉，右上角变成「已登录」。

登录后右上角的菜单里可以进账户页、看自己发布的故事、退出登录。

短码 15 分钟有效、只能用一次。**App 里不需要输入密码**，
发布令牌由服务器直接发到这台机器，不经过剪贴板。
连接可以随时在 App 里「断开」，也可以在网站账户页吊销。

发布目标就是官方站点，界面上不再需要填任何地址。
自建服务器或本地开发用
`flutter run --dart-define=TV_SITE=http://localhost:3000` 覆盖。

可见性两选一：**公开**，或**仅凭链接访问**（不出现在任何列表里，
只有拿到链接的人能打开）。

### 上传的到底是什么

只有导出目录里 `photos/` 和 `thumbs/` 的 WebP —— 已经剥掉 EXIF、
没有 GPS 的网页用图。**原图一张都不上传**，本机导出目录里出现任何非 WebP
文件，发布会直接中止而不是"跳过"。图片是从你的电脑**直传对象存储**的，
不经过我们的服务器。

### 再次发布 = 更新那一篇

同一份工作进度（草稿）发布过一次之后，App 会记住网站上那一篇的 id。
再点发布时按钮会变成**更新**：

- 公开链接**不变**，已经分享出去的地址继续有效；
- **不会再扣一次额度**；
- 这次没再选中的照片，会连同服务器上的文件一起删掉。

想另发一篇（而不是覆盖），点旁边的「改为新建一篇」——
那会当作全新的一篇，扣一次额度，得到一个新链接。

> 记住的是**草稿**，不是整个照片库。一个库里的每趟行程各自对应网站上的一篇。

### 你的公开主页

在网站账户页设一个主页地址（3-20 位小写字母、数字、下划线），
你的主页就是 `站点/u/你的名字`。上面按时间排列你所有**公开**的故事，
带分享按钮（Facebook / 微信二维码 / 复制链接给小红书）。

设成「仅凭链接访问」的故事不会出现在主页上 —— 那正是这个可见性的意义。

### 额度不够时

会明确告诉你还没有可用额度，并给一个去网站付款的入口。
**这时什么都没有上传**，付完款回来再点一次发布就行。

### 5.7.1 网站上的付款页

网站登录后进 **账户 → 订阅与额度**（`/account/billing`，中英文各一份）。
这一页回答三件事：

| 看什么 | 在哪 |
|---|---|
| 我现在能不能发布 | 顶部：Pro 订阅状态 / 剩余额度 |
| 怎么买 | 中部：Pro 年付 \$50、月付 \$8；额度包 \$5=2 篇、\$10=5 篇、\$25=15 篇 |
| 我付过什么 | 底部：付款记录（日期、档位、金额、加了几篇） |

- 额度**不过期**，和订阅可以并存；订阅期内发布不消耗额度。
- 换卡、取消订阅走「管理订阅」按钮，跳 Stripe 自助门户，不用联系人工。
- 公测期（注册满 100 人之前）发布免费，但付款入口照常开着，
  这期间买的额度一分不扣地留着。
- 付款成功跳回来时，网站会主动跟 Stripe 对一次账，
  **不依赖 webhook 是否及时到达**，所以不会出现"付了钱页面没反应"。

## 6. 照片库的目录结构

```
你的照片库/
  photos/2025/2025-09-12/          原件，按拍摄日期
    2025-09-12 14-30-22 IMG_1234.HEIC
    .tvmeta.json                   这一天的元数据（真相）
  catalog/                         索引与缓存，可整个删除后重建
    catalog.jsonl                  纯文本镜像，可以直接 grep
    thumbs/                        列表缩略图
    previews/                      全图查看用的大图
  TRAVELVIEW.md                    写给未来的说明
```

`.tvmeta.json` 跟着照片走——把某个日期文件夹拷到别处，元数据一起走。

## 7. 常见问题

**点开照片是一片黑？**
预览图损坏时会显示错误信息和一个「重新生成预览」按钮，点它即可。
如果连错误信息都没有、真的全黑，那是异常，请把终端里的报错发出来。

**照片显示成灰色方块？**
缩略图还在生成中。看状态栏右侧的进度，或者等后台预生成跑完。

**在访达里改了文件名会怎样？**
不会有问题。「重建索引」时会靠文件内容的哈希重新认出它，
不会重复导入，也不会丢标签。

**能删除照片吗？**
App 不提供删除。要删就在访达里删，然后「重建索引」。
这是刻意的设计——备份工具不该有删除按钮。

**旋转之后为什么校验报告说内容变了？**
正常。旋转改了 EXIF 方向标记，内容哈希因此变化，
App 会自动更新索引并保留全部标签。
